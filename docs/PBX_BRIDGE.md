# Private PBX Bridge

The PBX Bridge is a small service that runs inside the business phone-system
network. It gives Relay an outbound-only health signal without placing PBX
passwords or LAN access in the hosted console.

## Current scope

The first Bridge contract is intentionally report-only:

- the owner creates an enrollment credential in **Control center**;
- the credential is displayed once and stored by the installer, not in a
  browser bundle;
- the Bridge reports whether it is ready, degraded, or offline, and whether the
  installed call map is not applied, applied, or has drifted;
- an owner can revoke a Bridge credential immediately;
- the Bridge cannot change a call route through this heartbeat endpoint.

## Heartbeat contract

`POST /pbx-bridge/heartbeat`

Use the enrollment credential as a bearer token. The Bridge ID and credential
are generated by Relay; do not put either in source control or logs.

```json
{
  "version": 1,
  "event": "pbx_bridge.heartbeat",
  "bridgeId": "pbx_bridge_generated_by_relay",
  "sentAt": "2026-09-14T12:00:00.000Z",
  "payload": {
    "status": "ready",
    "callMapState": "applied",
    "agentVersion": "0.1.0"
  }
}
```

Valid values:

- `status`: `ready`, `degraded`, or `offline`
- `callMapState`: `not_applied`, `applied`, or `drifted`

A `ready` Bridge is an active private connection. The business call path is
only considered applied when that Bridge additionally reports
`callMapState: applied`. The reporting contract does not itself prove a call;
the owner must still run and record the controlled call-path tests in Phase 2.

## Next Bridge release

The next release adds an owner-approved change job: Relay presents the desired
map, the Bridge reads current PBX state, the owner approves the exact diff, the
Bridge applies it locally, and Relay stores a post-apply readback and rollback
record. That keeps every physical routing change explicit and auditable.
